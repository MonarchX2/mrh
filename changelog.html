Version 26.11.07

Patch 3
Improved
  • Sped up Reviewer PDF warm-path requests by batching the read-only issuance pre-check and the first shared storage-lease acquisition into a single parallel backend round trip, with automatic fallback to the sequential path.
  • Reduced Reviewer PDF post-sign backend work by merging issuance consumption, access auditing, and storage-lease release into one atomic database transaction when the merged audit contract is deployed.
  • Sped up repeat Reviewer PDF previews by caching Unicode text analysis (bidi levels, grapheme clusters, font selection) and fontkit shaping results across operations in the PDF worker.
  • Removed the unused retained-artifact path from the PDF worker and processor now that previews always encrypt during watermarking, lowering worker memory and simplifying download encryption.
Patch 2
Fixed
  • Fixed Reviewer PDF previews that could hang indefinitely on a slow-trickling signed download; the source fetch now has a total deadline on top of per-read stall protection.
  • Fixed retried Reviewer PDF issuances potentially consuming extra rate-limit slots when post-issue audit logging hit transient failures; audit retries now reuse one event ID and report a non-retryable audit error instead.
  • Fixed public PDF previews attempting oversized base64 transport through the backend; public PDFs now always use Drive preview.
Improved
  • Sped up Reviewer PDF warm-path requests with longer-lived session, account, index, and Drive-resource caches plus faster shared storage-lease acquisition.
  • Added real progress feedback to Reviewer PDF previews: measured download bytes, worker page-level watermark progress, and a live percentage that completes only when the first page renders.
  • Scaled Reviewer PDF client caches to device memory so low-RAM devices retain fewer multi-megabyte artifacts.
  • Expanded Reviewer PDF storage prewarming coverage for larger catalogs.
Patch 1
Fixed
  • Fixed Reviewer PDF previews and downloads running serially by pooling PDF workers so a preview and download can proceed in parallel.
  • Fixed a stale PDF viewer error covering an already-rendered preview; late failures no longer hide a successfully loaded document.
  • Fixed duplicate element IDs in the cloned quiz navigation controls that could break navigation buttons in review sessions.
  • Fixed toast notifications stacking duplicates; repeated messages now refresh a single visible toast.
  • Fixed service worker update checks paying an extra network round trip by deriving the release version from the registered worker URL.
  • Fixed app-shell navigation failing on non-root deployments by injecting the correct base path into cached HTML responses.
  • Bounded the Reviewer PDF client cache by retained byte size with recency-aware eviction to prevent excessive memory use.
Improved
  • Sped up Reviewer PDF previews and downloads with a two-worker pool, retained watermarked artifacts, page layout and glyph caches, and reuse of encrypted preview bytes for downloads.
  • Preconnected to private PDF Storage during authorization and added rate-limit overlays with cooldown timers on protected PDF links.
  • Warmed the pdf.js viewer while browsing the dashboard so the first PDF preview skips worker startup latency.
  • Upgraded the backend to v5.3.3 with shared/exclusive storage leases, bounded lease retries, cached session lookups, and opt-in PDF prewarming sweeps.
  • Vendored idb-keyval locally so storage no longer depends on a third-party CDN.
